# Skill: LiteLLM プロキシ利用量・負荷分散分析 (skill-litellm-usage)

## 概要
LiteLLM プロキシの利用ログを集計する `./scripts/show_usage.py` を呼び出し、内部ローテーションキー（`GEMINI_API_KEY_1` 〜 `4` 等）の負荷分散バランス、モデル別のトークン消費量、推定コストを評価して、自然言語で分かりやすくレポートする。

## Instructions
1. **対象日・引数の判定**:
   - ユーザーの要求から集計対象日を特定する（「今日」「本日」または指定なしの場合はオプションなし、過去日指定の場合は `--date YYYY-MM-DD`）。
2. **ログデータの取得**:
   - 基本的に JSON 形式で詳細データを取得するため、以下のコマンドを実行する:
     ```bash
     ./scripts/show_usage.py [--date YYYY-MM-DD] --json
     ```
   - 生の整形テキストレポートを求められた場合は `--json` なしで実行する。
3. **データの分析・評価**:
   - **全体総計**:
     - 総リクエスト数
     - 総トークン数（Prompt トークン + Completion トークン）
     - 総推定コスト ($)
   - **負荷分散（ロードバランシング）状況の評価**:
     - 各 API キー（`GEMINI_API_KEY_1` 〜 `GEMINI_API_KEY_4`）へのリクエスト数配分比率
     - 各キーのトークン消費量およびコスト
     - 負荷が適切に分散されているか、特定キーへの偏りがないか、または `OTHER / UNKNOWN` が多発していないかをチェック
   - **モデル別利用傾向**:
     - モデルごと（`gemini-flash-2`, `gemini-flash`, `gemini-flash-lite` 等）のリクエスト割合およびトークン消費比率
4. **レポートの出力**:
   - 以下の構成で整理されたサマリを回答する:
     - 📌 **全体サマリ** (リクエスト数 / トークン数 / コスト)
     - ⚖️ **負荷分散状況** (キー別のリクエスト配分比率 & 評価コメント)
     - 🤖 **モデル別利用状況** (各モデルの比率と主な用途傾向)
     - 💡 **インサイト / 留意点** (偏り、コスト高要因、異常ログの有無など)

## Output Contract
- マークダウン形式で視覚的に整理された利用量 & 負荷分散レポート
- 負荷分散の健全性・偏りに関するエンジニア視点での客観的評価コメント
