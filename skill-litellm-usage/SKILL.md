# Skill: LiteLLM プロキシ利用量・耐障害性・負荷分散分析 (skill-litellm-usage)

## 概要
LiteLLM プロキシの利用ログを集計する `./scripts/show_usage.py` を呼び出し、内部ローテーションキー（`GEMINI_API_KEY_1` 〜 `5` 等）の負荷分散バランス、モデル別のトークン消費量、推定コスト、フォールバックおよび RateLimit (HTTP 429) の発生状況を評価して、自然言語で分かりやすくレポートする。

## Instructions
1. **対象日・引数の判定**:
   - ユーザーの要求から集計対象日を特定する（「今日」「本日」または指定なしの場合はオプションなし、過去日指定の場合は `--date YYYY-MM-DD`）。
2. **ログデータの取得**:
   - 基本的に JSON 形式で詳細データを取得するため、以下のコマンドを実行する:
     ```bash
     ./scripts/show_usage.py [--date YYYY-MM-DD] --json
     ```
   - 生の整形テキストレポートを求められた場合は `--json` なしで実行する。
3. **データの分析・評価**:
   - **全体総計**:
     - 総リクエスト数
     - 総トークン数（Prompt トークン + Completion トークン）
     - 総推定コスト ($)
   - **負荷分散（ロードバランシング）状況の評価**:
     - 各 API キー（`GEMINI_API_KEY_1` 〜 `GEMINI_API_KEY_5`）へのリクエスト数配分比率
     - 各キーのトークン消費量およびコスト
     - 負荷が適切に分散されているか、特定キーへの偏りがないか、または `OTHER / UNKNOWN` が多発していないかをチェック
   - **RateLimit クォータ余裕度分析 (vs 公式基準)**:
     - `quota_margin_stats` をもとに、Google Gemini API 公式制限基準 (15 RPM / 1,000,000 TPM per key) に対する本日のピーク消費率および残りマージン (%) を分析
     - 1分あたりリクエスト数 (RPM): ピーク RPM と公式理論上限 (15 RPM × キー数) の対比・余裕度評価
     - 1分あたりトークン数 (TPM): ピーク TPM と公式理論上限 (1,000,000 TPM × キー数) の対比・余裕度評価
     - 日次累計リクエスト (RPD): 1キー平均消費数と到達目安に対する消化状況および残りマージン (%)
   - **耐障害性・フォールバック実績 (Resilience)**:
     - リトライ救済成功件数 (`retried_and_recovered_requests`): 一時的なレートリミットや障害が発生しても、プロキシの自動リトライ・キー切り替えによって救済されたリクエスト数
     - モデルフォールバック発動件数 (`model_fallbacks`): 上位モデルから下位モデル（例: flash → flash-2 → flash-lite）へ迂回して成功した件数
   - **RateLimit (HTTP 429) & エラー分析**:
     - 429 エラーの発生件数と分類: 日次クォータ枯渇 (`Daily Quota (RPD)`) vs 瞬間レート制限 (`RPM/TPM`)
     - どの API キーで RateLimit が発生しているかの特定（日次上限に達したキーの識別）
     - クライアントキャンセル (`499`) やサーバ過負荷 (`503`) 等のその他エラー傾向
   - **モデル別利用傾向**:
     - モデルごと（`gemini-flash`, `gemini-flash-2`, `gemini-flash-lite`, `text-embedding-ada-002` 等）のリクエスト割合およびトークン消費比率
4. **レポートの出力**:
   - 以下の構成で整理されたサマリを回答する:
     - 📌 **全体サマリ** (リクエスト数 / トークン数 / コスト)
     - 📈 **RateLimit クォータ余裕度** (公式上限基準 vs ピーク消費率、残りマージン %、余裕度判定)
     - ⚖️ **負荷分散状況** (キー別のリクエスト配分比率 & 評価コメント)
     - 🛡️ **耐障害性・フォールバック状況** (リトライ救済数、フォールバック発動実績とサービス継続性評価)
     - ⚠️ **RateLimit / エラー分析** (429の発生有無、枯渇しているキーの特定、原因分類)
     - 🤖 **モデル別利用状況** (各モデルの比率と主な用途傾向)
     - 💡 **インサイト / 改善助言** (クォータ枯渇キーへの対応、プロキシ耐障害性の評価、推奨設定等)

## Output Contract
- マークダウン形式で視覚的に整理された利用量 & 耐障害性・負荷分散レポート
- 負荷分散の健全性・耐障害性・RateLimit 対策に関するシニア・インフラ・エンジニア視点での客観的評価コメント
